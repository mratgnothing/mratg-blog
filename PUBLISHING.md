# Publishing Workflow

## Recommended GitHub + Netlify Flow

1. Create or use a GitHub repository for this folder.
2. Push the Astro source code.
3. In Netlify, choose **Add new site > Import an existing project**.
4. Select the GitHub repo.
5. Use these build settings:

```text
Build command: npm run build
Publish directory: dist
```

Netlify will run `npm install` and `npm run build` on every GitHub push.

## Add A New Article

Run the content generator:

```bash
npm run new:post -- --title "文章标题" --description "首页卡片摘要" --category "Tech Note" --column tech-note --tags "SDD-YOLO,Ascend"
```

By default the generated article is a draft. The `column` value controls which
`/columns/.../` archive page receives the article. Edit the created Markdown
file, then publish it by changing `draft: true` to `draft: false`, deleting the
draft line, or creating it directly with `--publish`.
When you revise an article later, also update its `updated` timestamp. The
homepage only shows the most recently updated articles; `/posts/` shows the full
archive.

You can still create a file manually in `src/content/posts/` with this
frontmatter:

```yaml
---
title: "文章标题"
description: "首页卡片摘要"
category: "Tech Note"
column: "tech-note"
tags:
  - "SDD-YOLO"
date: "2026-06-08"
updated: "2026-06-08T14:30:00+08:00"
---
```

Then write Markdown under it. The homepage automatically lists recent non-draft
posts by `updated`, falling back to `date` when `updated` is absent.

## Add A New Column

Run:

```bash
npm run new:column -- --name "栏目名称" --description "栏目说明" --accent teal --group writing
```

The new column file appears in `src/content/columns/` and is automatically shown
on the homepage writing board or journal shelf. Supported groups are `writing`
and `journal`. Supported accents are `berry`, `teal`, `gold`, `violet`, and
`green`.

## Add A Diary Entry

Run:

```bash
npm run new:diary -- --title "今天的小记录" --datetime "2026-06-08T21:40:00+08:00" --tags "Life,Campus"
```

Diary files appear in `src/content/diary/`. They are for short, time-specific
notes and are rendered together on the homepage timeline in chronological order.

## Local Preview Before Push

Astro is not meant to be checked through `file:///.../index.html` because routes
and root-based assets are generated by the dev/build server.

## Article Images

Store article images in `public/assets/posts/` and reference them from Markdown
with `/assets/posts/file-name.jpg`. Prefer this figure pattern when a caption is
useful:

```md
<figure class="article-figure">
  <img src="/assets/posts/file-name.jpg" alt="Describe the image." loading="lazy" />
  <figcaption>图片说明。</figcaption>
</figure>
```

Avoid `C:\...` or `D:\...` paths in posts; those only work on the local machine.

NetEase Cloud Music playlists can be embedded with:

```md
<div class="music-embed">
  <iframe title="网易云音乐歌单播放器" src="https://music.163.com/outchain/player?type=0&id=PLAYLIST_ID&auto=0&height=430" width="100%" height="450" frameborder="0" allow="encrypted-media"></iframe>
  <p><a href="https://music.163.com/#/playlist?id=PLAYLIST_ID" target="_blank" rel="noreferrer">打开网易云歌单</a></p>
</div>
```

## Comments

Article and diary comment boxes currently store comments in browser
`localStorage`. They require a username and email, and support text, emoji, and
one image under 2MB. For public shared comments on Netlify, add a backend or
hosted comment service before relying on them in production.

Use this workflow instead:

```bash
npm install
npm run dev
```

Open the localhost URL printed by Astro while editing.

Before pushing:

```bash
npm run build
npm run preview
```

Open the preview URL and check the homepage, project cards, images, and article
routes. After that, commit and push to GitHub; Netlify will deploy the new build.

## Drafts

Set `draft: true` to hide a post from the homepage and from generated routes.
