# 高校风云线上匹配与 AI 对战

本次在原有单机网页的基础上增加独立游戏服务、真人匹配和策略 AI。实体规则依据为 2026-09-02 审计修订的 v0.5，线上玩法单独标识为 `quick-v1`。网站页内“开局须知”列出主要差异，不将快速版测试结果当作实体完整版平衡结论。

## 玩家使用

在 `/games/gaoxiao-fengyun/` 输入昵称、选择高校和 3–6 人桌：

- **开始匹配**：相同人数的玩家进入公共队列。满桌立即开局，否则从本批第一人入队开始等待 20 秒，届时以 AI 补齐。不同人数桌分别匹配。
- **与 AI 练习**：立即创建个人练习桌，其余位置全部为 AI。
- **取消匹配**：尚未分桌时撤销排队；若同一时刻已经分桌，则显示已分配房间，玩家可选择退出。
- **刷新重连**：浏览器本地保存会话和房间号，重新打开同一浏览器即可恢复。不要清理浏览器网站数据。
- **超时托管**：每次操作 90 秒，超时后 AI 接管；点击“恢复操作”重新接手。真人不会因网络抖动立即被踢出。
- **退出对局**：经确认后由 AI 接替，原玩家不可再回到本局，可以重新匹配。

每个浏览器会话独立；使用不同浏览器或不同无痕窗口测试多个真人。同桌选到相同高校时，按服务器入队顺序保留先选者，后选者分配其他学校，并记录校史。

## AI 方法

AI 是不依赖外部大模型 API 的启发式策略玩家，无需配置模型密钥。

规则引擎先枚举当前合法行动，AI 再计算收益：剩余时代的院系收入、资源短缺、升级能否超过对手、评估临近程度、生源阈值、人才匹配与工程当前前二竞价。AI 会比较追加投入能增加多少声望，避免无收益投入。不同 AI 略偏建设、科研或均衡路线。

AI 与真人调用同一个 `applyAction`。服务端只接受当前版本的合法行动 ID，客户端不能提交资源余额、声望或院系。AI 不读取未来事件、洗牌种子或玩家凭证。

## 架构与接口

- Astro 保持静态 Pages 发布，游戏页面及 336 张牌库与原博客一起构建。
- 新增 `mratg-gaoxiao-game` Worker，通过同域 `/api/gaoxiao/*` 路由提供游戏接口，不修改其他页面/API。
- Durable Objects：每个桌位数一个公共匹配协调器；每个对局一个独立 `GameRoom`。练习队列按玩家独立。
- 使用 SQLite 存储同步读改写；分桌结果先持久化，再幂等创建房间，重复轮询不会重复开局。
- Durable Object alarm 驱动排队过期、AI 行动、超时托管和清理。房间最长保留 6 小时；终局约保留 1 小时；所有真人退出后约 1 分钟清理。
- 客户端 1.5 秒轮询、90 秒行动限时，使用服务端时间计算倒计时。
- 会话为随机 256 位 bearer 值，仅保存在浏览器并放在 Authorization 请求头；服务端用其 SHA-256 摘要作为玩家标识。日志和页面不输出凭证。
- 匹配租约 15 秒，公共队列限制每来源 IP 每分钟 12 次新入队，协调器限制 1000 张有效票据；JSON 请求最多 4 KiB。私人练习实例的限流仅针对自身实例，未做跨实例全局限流。

| 接口 | 用途 |
| --- | --- |
| GET `/api/gaoxiao/health` | 版本、就绪与等待时间 |
| POST `/api/gaoxiao/session` | 创建匿名会话 |
| POST/GET `/api/gaoxiao/match` | 入队与保活轮询 |
| POST `/api/gaoxiao/match/cancel` | 撤销匹配 |
| POST `/api/gaoxiao/practice` | 独立 AI 练习 |
| GET `/api/gaoxiao/room/:id/state` | 已入桌玩家获取自己的视图 |
| POST `/api/gaoxiao/room/:id/action` | 版本校验、请求幂等、行动校验 |
| POST `/api/gaoxiao/room/:id/resume` | 恢复真人控制 |
| POST `/api/gaoxiao/room/:id/leave` | 退出并释放匹配票据 |

## 上线顺序与回退

1. `wrangler whoami` 确认目标账户；登录过期时运行官方 `wrangler login`。
2. `npm run deploy:gaoxiao` 创建 Worker、两个 SQLite Durable Object 命名空间并绑定指定域名的游戏 API 路由。
3. 用线上 `https://mra-t-g-blog.cn/api/gaoxiao/health` 核验 Worker。
4. `npm run build` 后，将 `dist/` 发布到现有 `mratg-pixel-blog-git` Pages 生产项目；源代码提交到 `mratgnothing/mratg-blog`。不要把旧 checkout 的主页或未发布内容覆盖到生产。
5. 在线上再次测试两个独立会话、匹配、AI 补位、行动、刷新与手机布局，退出测试房间。

回退前端可使用 Pages 的上一部署；Worker 可使用 `wrangler rollback`。数据库规则标识为 `quick-v1`，后续不兼容规则应创建新的版本命名空间，避免把进行中的对局按新规则解释。
