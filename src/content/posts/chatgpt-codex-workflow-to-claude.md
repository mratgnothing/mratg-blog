过去几个月，我的大部分工程和研究工作都压在 ChatGPT / Codex 上：WAVE 的云端和客户端、这个像素博客、VLM 论文的实验与写作，还有一堆零碎的 QQ、FPGA、Multisim 小任务。Codex 用久了，积累下来的不只是代码，还有一套「它知道我怎么干活」的默契。

10 月 29 日，我决定把这套工作流搬进 Claude。动手之前我以为这是一次文件迁移，做完才发现，**真正要迁移的是「接手能力」**——一个全新的 Agent 打开项目时，能不能不靠我重新讲一遍，就知道该读什么、该信什么、该停在哪。

## 第一步：别搬聊天记录，搬「现行入口」

最直觉的做法是把旧对话全导出来塞给新模型。但旧对话里混着失败尝试、过期计划和已经撤回的结论，直接喂进去只会让新 Agent 继承我的历史包袱。

所以这次只做了三件事：

- **项目原文留在原位。** 三个项目——WAVE（cloud / client / app / sdk 四个独立仓库）、博客、SHS/VEH 论文——不复制业务数据，只给出每个项目的真实目录和阅读顺序，比如博客先读 `AGENTS.md → PROJECT_CONTEXT.md → LOCAL_HANDOFF.md → PUBLISHING.md`。
- **Codex 的记忆做成只读导出。** 原来的 Markdown 记忆和 rollout 摘要被导出到一个共享上下文库，带来源 SHA256，并做了凭据脱敏（扫描时识别并处理了 1 处凭据样式内容）。原始 `.codex` 目录继续隔离，Claude 读不到、也改不了。
- **建一个文档索引。** 当前索引了 8000 多份文档和结构化资料、136 份记忆文件，跳过依赖、缓存、Git 内部和目录链接。

## 第二步：让 Claude 自己去找，而不是我去贴

上下文库通过一个本地 MCP 服务 `codex-context` 暴露给 Claude，只有四个工具：

| 工具 | 作用 |
|---|---|
| `context_bootstrap` | 读项目规则、路径、记忆摘要和阅读顺序 |
| `context_search` | 检索原文或完整记忆，返回来源 ID 和行号 |
| `context_read` | 按来源 ID 分页读全文 |
| `context_list` | 分页列出全部索引 |

再在 Claude Code 的全局 `CLAUDE.md` 里写一段跨 Harness 规则和两套记忆摘要。这样新对话一开始就知道：当前用户要求 > 项目现行文件和真实输出 > 带日期的历史记忆。记忆是某个时刻的快照，冲突时以现场为准。

## 第三步：把「不能做什么」写得比「能做什么」更清楚

这一步是整个迁移里我最在意的。Codex 时代我给过很多一次性授权：某次 GPU 预算、某次发布、某次清理。如果新 Agent 读到这些记录，把它们当成「用户曾经同意过」，后果会很麻烦。

所以规则里明确写着：

> 历史授权不能作为重启实验、继承旧预算或发布的依据。

验收时我专门让一个全新的、不持久化的 Claude Code 会话去读三个项目，结果它：

- 自动看到了跨 Harness 规则和两套记忆摘要；
- 用工具实际读取了三个项目的现行文件，并检索到了 VEH-F1 的历史记录；
- 识别出论文项目最新状态是 10 月 29 日的结果同步复核；
- **拒绝**把旧实验或旧预算当成重启授权，也知道博客发布需要单独授权。

第一轮验收其实没过：自动摘要根本没加载进来。修好以后复测才通过。两轮 CLI 自带的成本估算字段加起来大约 0.21 美元——这是估算字段，不是账单。

## 第四步：虚拟机里的 Claude，宿主机上的手

我的 Claude 跑在 VMware 虚拟机里，而 QQ、Vivado、Multisim、FreeCAD 这些东西都在宿主机上。文件可以通过共享盘看到，但**进程、COM、注册表、驱动和 localhost 不会跟着共享过来**。在虚拟机里执行一条命令，不等于在宿主机执行。

这里的解法是保留一条已有的 Cloudflare DevSpace 通道：普通文件读写用虚拟机本地工具，真正需要宿主机进程的任务再通过这条通道执行。原来 Codex 的技能（博客导入、QQ 收发、Vivado、Multisim、FreeCAD 等）复制成 Claude 技能，每个都加了一段「VMware 执行适配」，写清楚路径映射和哪些事必须去宿主机做。

这篇文章本身就是用迁移过来的「博客导入」技能写的：Claude 读了技能说明和博客仓库的现行文档，发现收件箱里还躺着旧条目（直接跑导入会再生成一批 `-2` 重复文件），于是改用单独的批次目录导入，只提交这次新增的文件。

## 还没迁过来的

说清楚边界：这次完成的是**文档、记忆和接手能力**的迁移。

- 宿主机的 GPU、Docker、QQ、USB 设备和 localhost 服务没有随文件共享迁移，每次仍要检查任务实际跑在哪台机器上；
- 无文字层的 PDF 需要另做 OCR，Office 抽取虽然实现了，但这次索引里没有 Word 样本，不算实测通过；
- Claude Desktop 普通聊天不会读 Claude Code 的 `CLAUDE.md`，需要手动让它调用 `codex-context`；
- 历史记忆永远不代替当前的源码、进程和结果核验。

## 小结

换一个 AI 工具，本质上像给项目换一个新同事。你不会把五个月的聊天记录甩给新同事，而是给他一份交接文档、一个能搜的资料库，以及一张「这些事先问我」的清单。

这次迁移做的就是这三样东西。至于 Claude 和 Codex 谁更好用——那得再干几个月活才有资格说。
