![手机、网络桥接层和桌面 Claude Code 之间的交互结构](/assets/posts/sep-oct-2026-mobile-bridge.svg)

9 月 26 日，我有了一个颇为朴素的需求：电脑上的 Claude Code 已经在执行长任务，但我不可能一直守在电脑前。如果出门只带手机，能不能像打开聊天软件一样，继续读它的回复、补一条指令、切一个会话？

于是，问题从「怎么远程控制终端」变成了「怎样把桌面 Agent 的完整会话体验搬到 Android」。

## 第一版：让电脑继续干活，手机负责接入

最初先搭了一个本地浏览器入口，再接上公网 HTTPS 通道。它需要保留电脑上的会话和项目上下文，同时让手机看得到历史会话、模型配置以及运行状态。

这套结构很快让我意识到，**移动端不是一个迷你终端窗口**。一段长推理会包含普通回答、Markdown 表格、数学公式、工具调用、思考过程、运行中的状态变化。只是把文本吐在网页上，体验远远不够。

真正需要处理的是：

- 会话的「进行中」和「已经结束」必须由可靠状态决定，不能靠某个按钮有没有变灰来猜。
- 手机端读历史时，界面不能突然跳回回复开头。
- 表格和公式不能以原始标记堆成一团。
- 即使桌面任务正在执行，手机也应该能够执行明确的中止或交互动作；这和只读浏览是两种模式。
- Android 的状态栏、导航栏和顶部操作区必须分开，不能把重要按钮藏在系统区域下面。

## APK 能打开，只是工程的起点

那几天我继续尝试 Android APK。第一版安装后发生过闪退；之后又陆续遇到旧会话打不开、创建新会话未触发、对话列表拥挤、运行状态误判、Markdown 渲染不完整等问题。

这些错误其实很有代表性。一个「套壳浏览器」似乎很快就能做出原型，但只要需要和真实 Agent 状态双向同步，它就立刻变成了前后端状态机、异步事件流、渲染器和安卓系统 UI 的综合问题。

> 手机只负责交互，桌面才是真正持有项目文件、环境、终端与 Agent 上下文的执行端。

## 我想做的，其实是「不中断」

以前我觉得移动远程的重点在于「能够连接」。做完这一轮才发现，更重要的是连接前后，桌面的工作有没有被打断：已开启的会话是否保持原状、项目的配置是否仍然适用、失败后能否重新进入、恢复时会不会重复触发任务。

这也是为什么 9 月底的多轮修复远比第一版开发更费精力。它不是已经完美交付的产品，更像一个边用边修的个人基础设施。

我希望以后可以在实验室开一个任务，坐地铁时看进展，发现方向偏了就从手机改指令。终端不一定要随身携带，但工作的上下文应该可以随身携带。

> 记录范围：2026 年 9 月 26—30 日。本文只讨论架构与体验问题，不公开远程接入地址、认证信息或配置凭据。
